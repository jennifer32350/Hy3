# Hy3 Data Analyst MCP v0.2 开发计划

> 产品范围与验收标准见 [v0.2 PRD](product-requirements-v0.2-cn.md)。
> Schema、执行语义和安全边界见 [v0.2 技术规格](technical-spec-v0.2-cn.md)。

## 1. 升级目标

v0.2 的目标不是简单增加更多工具，而是把当前“单次、单操作的数据查询工具”升级为
“能够完成多步骤分析、提供可追溯证据、生成可展示结果的数据分析助手”。

核心成功标准：用户提出一个复合问题后，系统能够安全地完成数据质量检查、多个确定性计算、
异常解释和可视化输出，而不需要用户把问题手工拆成多次调用。

## 2. 当前版本的主要限制

1. 每个问题只能规划一个 `AnalysisPlan`，无法连续执行“筛选 → 分组 → 对比 → 异常分析”。
2. 只有 7 类基础操作，缺少安全筛选、交叉分析、期间对比、占比、变化率和分布分析。
3. 计算结果只有一组 Evidence，复杂结论缺少逐条证据编号和完整的数据血缘。
4. 缺失值、重复值和类型问题只能被发现，不能在分析计划中声明明确的处理策略。
5. 图表工具只返回建议，不产生可直接查看的图表或可交付规格。
6. 输出以底层 JSON 为主，缺少面向业务阅读的摘要、发现、建议和风险分层。
7. 尚无代表真实任务难度的评测集，无法量化升级前后的效果差异。

## 3. 产品边界与安全原则

v0.2 继续坚持以下约束：

- Hy3 负责理解问题、规划和解释，不直接计算最终统计值。
- Pandas/NumPy 负责确定性计算，所有操作必须来自白名单执行器。
- 不执行模型生成的 Python、Shell、SQL、表达式或 `DataFrame.query()`。
- 筛选条件和派生指标使用受 Pydantic 约束的结构化语法，不使用字符串表达式。
- 每个工作流限制最大步骤数、最大记录数、模型调用次数和执行时间。
- 原始数据仍限制在 `HY3_DATA_DIR` 内；生成物写入单独的受限输出目录。
- 保持现有三个 MCP 工具兼容，优先扩展可选参数和返回字段。

v0.2 暂不包含数据库连接、远程 URL、预测模型训练、任意代码执行和通用自主 Agent。
多表 Join、Excel/Parquet 和高级统计建模放入 v0.3 候选范围。

## 4. 分阶段路线图

### 阶段 0：建立真实效果基线

预计：1～2 天。

任务：

- 创建 3～5 个不同类型的脱敏示例数据集，覆盖销售、运营、用户行为和数据质量问题。
- 建立至少 30 个评测问题，分为基础统计、复合分析、趋势、异常、质量和可视化六类。
- 为每个问题记录预期操作、关键数值、必须发现的问题和不可接受的幻觉。
- 保存当前 v0.1 的结果，形成升级前基线。

验收：

- 评测可离线重复运行；确定性计算具有精确断言。
- 能量化计划成功率、数值正确率、证据引用率和端到端成功率。

### 阶段 1：多步骤安全分析工作流（最高优先级）

预计：4～6 天。

任务：

- 将单个 `AnalysisPlan` 扩展为 `AnalysisWorkflow`，允许 1～6 个有序步骤。
- 每个步骤具有稳定 `step_id`、操作、输入、参数、目的和依赖关系。
- 增加工作流级校验：列名、依赖、步骤上限、结果上限及禁止循环依赖。
- 逐步执行并生成 Evidence Ledger；后续步骤只能引用已验证的中间结果。
- 任一步骤失败时返回具体失败位置、已完成证据和可操作的修复提示。
- 保留单步骤计划兼容层，避免破坏现有客户端和测试。

第一批新增白名单操作：

- `filter_rows`：等于、不等于、包含、范围、日期范围和空值判断等结构化条件。
- `multi_aggregate`：同一次分组对不同字段执行多个聚合。
- `value_counts`：类别频数和占比。
- `distribution`：分位数、分箱和离散程度。
- `period_compare`：环比、同比或指定期间的绝对变化与变化率。
- `pivot_table`：受限行列维度和聚合函数的交叉分析。
- `derived_metric`：仅允许加减乘除、常数和真实数值列的结构化指标。

验收：

- “比较各区域销售与利润、定位异常并解释影响”能一次完成至少三个计算步骤。
- 每个最终数值都能追溯到具体步骤和 Evidence ID。
- 无效列、无效依赖、除零和过大工作流均被安全拒绝。
- 模型输出仍不能触发任何动态代码或表达式执行。

### 阶段 2：数据质量与分析口径

预计：3～4 天。

任务：

- 在计划中增加显式数据处理策略：忽略、保留或拒绝缺失值，是否去重，类型转换方式。
- 生成分析前后行数、排除原因、受影响字段和处理警告。
- 增加业务口径声明：聚合方式、分母、时间粒度、异常规则和排序规则。
- 对疑似金额、百分比、日期和 ID 字段提供更稳健的语义类型判断。
- 默认只在内存中处理数据，不改写原始文件。

验收：

- 结论明确说明使用了多少行、排除了多少行以及原因。
- 重复记录和缺失值不会静默改变统计结果。
- 数值字符串、日期异常和无穷值具有稳定的测试覆盖。

### 阶段 3：可信报告与追问体验

预计：3～4 天。

任务：

- 将结果升级为结构化报告：`executive_summary`、`findings`、`evidence`、
  `anomalies`、`recommendations`、`limitations` 和 `warnings`。
- 每条 Finding 必须引用一个或多个 Evidence ID；无证据时禁止输出强结论。
- 区分“数据事实”“模型解释”和“建议”，避免把推断写成事实。
- 增加置信表达：证据充分、样本不足、相关而非因果等。
- 返回建议追问，帮助客户端继续分析，但不在 Server 内维护隐式会话状态。
- 提供 `concise` 与 `detailed` 两种输出模式。

验收：

- 评测集中 100% 的数值性 Finding 都具有有效 Evidence 引用。
- 删除某条 Evidence 后，解释器不能继续声称对应结论。
- 报告能直接被 Cursor/CodeBuddy 展示，而不要求用户阅读底层 JSON。

### 阶段 4：真正可见的可视化结果

预计：3～5 天。

任务：

- 先输出经过严格 Schema 校验的图表规格和用于绘图的确定性聚合数据。
- 增加受限的本地图表渲染器，支持 bar、line、scatter、histogram 和 box。
- 生成 PNG，并通过 MCP 图像内容或受限输出路径返回给客户端。
- 支持标题、轴标签、图例、排序、Top-N、缺失值说明和异常点标注。
- 图表下附数据口径和 Evidence ID，确保图文一致。
- 增加 `HY3_OUTPUT_DIR`、文件名净化、数量上限和旧文件清理策略。

验收：

- 示例问题能返回两张实际可查看的图，而不只是文字建议。
- 图表所用数值与 Evidence 完全一致。
- 路径穿越、任意覆盖和输出目录外写入均被拒绝。

### 阶段 5：评测、性能和真实客户端验收

预计：2～3 天。

任务：

- 对 30 个以上评测问题运行 v0.1/v0.2 对比。
- 增加多步骤计划、执行链、证据引用、图表渲染和安全边界测试。
- 对大行数数据增加采样策略说明和执行耗时指标。
- 在 Cursor 和 CodeBuddy 中验证复合提问、追问、错误恢复和图像展示。
- 更新中英文 README、架构、安全说明、演示脚本和录屏。

发布门槛：

- 核心评测端到端成功率不低于 85%。
- 数值正确率为 100%；所有数值结论都有 Evidence 引用。
- Ruff、Mypy、Pytest 和 Windows/Ubuntu CI 全部通过。
- 项目覆盖率保持不低于 85%，新增核心执行器分支重点覆盖。
- 两个真实 MCP 客户端完成验证，不泄露 API Key 和个人路径。

## 5. 推荐迭代顺序

建议拆成三个可独立演示的里程碑：

1. **v0.2-alpha：复合分析可用**
   完成阶段 0～1。重点证明一个问题可以触发多个安全计算步骤。
2. **v0.2-beta：结果可信且易读**
   完成阶段 2～3。重点证明数据口径明确、结论可追溯。
3. **v0.2：结果可展示**
   完成阶段 4～5。重点证明客户端能直接展示报告和图表。

## 6. 第一轮开发任务清单

第一轮只做 v0.2-alpha，按以下顺序实施：

1. 新建评测数据和 30 个问题的机器可读清单。
2. 为当前 v0.1 运行并保存基线结果。
3. 设计 `AnalysisWorkflow`、`AnalysisStep` 和 `EvidenceItem` Schema。
4. 实现工作流校验器与多步骤执行编排。
5. 实现 `filter_rows`、`multi_aggregate`、`value_counts` 和 `period_compare`。
6. 改造 Planner，使其生成有界工作流并只允许一次修复。
7. 改造 Interpreter，使所有结论引用 Evidence ID。
8. 添加单元、集成、协议和真实 Hy3 冒烟测试。
9. 使用销售示例完成一次终端演示，再进入 Cursor 验证。

在 v0.2-alpha 验收前，不并行开发图表渲染和多文件分析，避免一次改变太多层导致效果无法归因。
